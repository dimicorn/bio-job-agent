# Contributing to bio-job-agent

## Environment

```sh
./setup.sh          # or: uv sync && uv run playwright install chromium
```

`uv sync` also installs the dev dependencies (ruff, pytest).

## Checks

```sh
uv run ruff check app tests
uv run ruff format --check app tests
uv run pytest
```

Default tests are offline; live checks are opt-in (see the
[README](README.md#development-and-tests)). The GitHub Actions
[tests workflow](.github/workflows/tests.yml) runs the same checks as the `test` job on every
push and pull request.

## Commits

Every commit message follows [Conventional Commits](https://www.conventionalcommits.org/):
`feat: …`, `fix: …`, `docs: …`, `refactor: …`, `perf: …`, `style: …`, `test: …`, `build: …`,
`ci: …`, `chore: …`, optionally with a scope such as `feat(apply): …`; mark breaking changes
with `!` (`feat!: …`) or a `BREAKING CHANGE:` footer.

The prefix decides the CHANGELOG section. Pull requests are merged with merge commits (no
squash), and git-cliff skips merge commits, so each change appears in the CHANGELOG once, under
the subject of the branch commit that made it: write every branch commit, not only the PR
title, in this form. Give the PR a Conventional Commit title too.

History from before Conventional Commits were adopted is sorted by its leading verb (Add,
Implement, Fix, Handle, …) through the parsers in `cliff.toml`; new commits do not rely on that.

## Protected main

`main` accepts changes only through pull requests whose `test` check has passed, merged with a
merge commit. Do not push to `main` directly. To bring a branch up to date, merge `main` into
it rather than rebasing.

## Releases and CHANGELOG

The package version comes from the git tag (hatch-vcs): on the tag `v0.2.0` it is `0.2.0`,
after it `0.2.1.devN+g<commit>`. Do not edit it in `pyproject.toml`; the current one is
`uv run bio-jobs --version`.

CHANGELOG.md is generated by git-cliff from the commit history using `cliff.toml`. A release
also goes through a pull request:

```sh
git switch -c release/v0.2.0 main
uvx git-cliff --tag v0.2.0 -o CHANGELOG.md
git commit -am "chore(release): v0.2.0" && git push -u origin release/v0.2.0
gh pr create --fill
# after the PR is merged:
git switch main && git pull
git tag -a v0.2.0 -m v0.2.0 && git push origin v0.2.0
```

Pushing the tag runs `.github/workflows/release.yml`, which publishes a GitHub Release with that
version's CHANGELOG section. To preview what the next release will contain:
`uvx git-cliff --unreleased -o -` (without `-o -` git-cliff overwrites CHANGELOG.md).
